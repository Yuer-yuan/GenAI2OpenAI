# 整段对话的图片预算回归

学校 DeepSeek 部署按整个 prompt 限制最多 20 张图片，包括已读过的历史截图。旧版本在 25 张历史图后再读 1 张新图，实际复现了 `At most 20 image(s) may be provided in one prompt`。外层 502 和 LiteLLM 的 fallback 提示并不改变这个输入限制，原样重试不会解决。

修复在 Anthropic 转换和 OpenAI 原生图文准备阶段限制总图数：超限时合并完全相同的内联图片，保留当前用户附件、待处理工具图片，再优先保留较新的历史像素。退役的历史图片会变成明确的文字标记，原有观察、调用 ID、说明与图文顺序保留。若当前图片自身超过预算，本地返回要求分批读取的 400，流式请求也在开始前拒绝，不会静默丢弃当前图片。URL 指向的内容可能变化，因此不按相同 URL 合并。

## 实测结果

所有模型请求都使用学校 `deepseek`，没有付费 GPT、辅助视觉模型或 OCR。每次请求先携带 25 张不同历史图，再通过 Read 工具结果返回新图。较早的文字观察只涉及旧图，不包含本题答案。

| 检查 | 结果 |
| --- | --- |
| 旧版本，25 张历史图 + 1 张当前图 | 上游拒绝：最多 20 张 |
| 新版本，OCR、图形计数、多图比较，各 2 组新内容 | 6/6 通过，14/14 字段正确 |
| 去掉当前图、仍保留 25 张历史图的对照 | 6/6 通过，未知字段均返回 null |
| 新版实际模型请求错误 / 无图猜出答案 | 0 / 0 |
| 本地回归 | 78 项通过 |

有图请求原始共 26 或 27 张，预算处理后为 20 张；当前图片仍在。无新图对照也会将 25 张历史图压到 20 张，但不应从无关旧图猜测当前任务。答案只保存在评分端，未加入提示词、文件名或 PNG 元数据。测试覆盖文字、计数、图片顺序与计数差，检查答案而非仅检查 HTTP 200。这仍是小样本合成图回归，不能保证任意复杂图片都正确。

最终验收使用 seed 71961、71962。开发阶段先使用另一组内容确认链路，修复系统提醒对当前附件判定的影响后，再冻结代码运行本组验收；没有根据本组答案继续调整协议。模型生成与网络延迟不可固定，复跑可能波动。报告保留本次源码 SHA256。

## 复跑

先启动本地服务，在项目目录执行：

```bash
uv run --locked --group vision python tools/benchmark_vision.py --models deepseek --history-images 25 --cases ocr shapes multiple_images --repeats 2 --seed 71961
uv run --locked python -m unittest discover -s tests -q
```

完整九类视觉能力的首次验收保留在 [vision](../vision/README.md)。旧像素退役后，需要精确对照旧图时应重新读取原始文件；保留的文字观察无法替代缺失的像素细节。
